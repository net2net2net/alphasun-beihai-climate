## 三、维护方式

```bash
# 刷新全局清单（并重新生成本文档）
node tools/sync-releases.js --list --export-md

# 归档最新发布版本的产物到本地（默认策略，只保留最新版本）
node tools/sync-releases.js --download

# 只看下载计划，不下载不写盘
node tools/sync-releases.js --download --dry-run

# 临时补某一个历史版本
node tools/sync-releases.js --download --only v8.2.0

# 显式归档全部版本
node tools/sync-releases.js --download --all

# 清理本地非最新版本的归档目录（先列清单，再交互确认）
node tools/sync-releases.js --prune-older

# 只读校验（GitHub digest / 本地实算 / manifest 三方比对）
node tools/sync-releases.js --verify
```

下载的每个资产都会用 GitHub 资产 API 提供的 `digest`（sha256）做完整性校验，
校验不通过的文件会被改名 `*.corrupt` 隔离并重新下载；已归档且校验通过的文件在
后续执行中自动跳过，因此中断后可直接重跑续作。

**清理旧版本**：`--prune-older` 会先打印待删目录清单与体积，再要求确认（交互式终端
询问 y/N；非交互环境需显式加 `--yes`），默认不会删除任何东西。最新发布版本的目录
与 `_index.json` 永远不会被删。
